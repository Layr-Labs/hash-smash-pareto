## 1. Target and relation

Target `blake3-r3-prefix-v1` (the benchmark's blake3 profile at 3 rounds). The two colliding messages are 64 bytes, M(x) = K || LE32(x): the 32 bytes K (words m0..m7 = 0x80000000, 0, 0x80000000, 0, 0x70000000, 0, 0, 0, little endian; hex 0000008000000000000000800000000000000070000000000000000000000000) followed by the 256-bit integer x (words m8..m15, little endian). It is one chunk of one block: chaining value IV, counter 0, block length 64, flags 11 = CHUNK_START | CHUNK_END | ROOT, 3 rounds with the BLAKE3 message permutation between rounds, digest = the 8 words v[i] XOR v[i+8] (i < 8), little endian (this is `verifier/blake3.py:blake3(M(x), 3)`). Write f(x) for the digest read as a 256-bit little-endian integer.
The walk is on g(x) = f(x) XOR q, where q is the fixed 256-bit mask (weight 124) of the polarities of the 256 digest planes of the circuit that the generator of Section 3.2 builds; q is printed by `python3 bsrho.py --ledger`. g(x) = g(y) if and only if f(x) = f(y): XOR with a constant is a bijection. The attack outputs x != y with g(x) = g(y), hence f(x) = f(y), and M(x) != M(y) are two distinct 64-byte messages with equal complete 256-bit digests (a 64-byte string is in the profile's message domain).
The program was compared outside the shipped experiments (`ext/ref_check.py`, not shipped) with the organizer reference `verifier/blake3.py:blake3(K || x, 3)`: the scalar digest on 2,048 random x, the bit-sliced step (stored planes XOR q) on 2,048 lanes, the packed recovery circuit on 448 values: 0 differences in each. The program's selftest (`python3 bsrho.py --selftest`) compares the step with the scalar compression on 4,096 lanes and on 4,096 lanes chained for 7 steps, executes the register-allocated code on a register file, checks the width-18 chain, the packed circuit, the table against a dictionary and the recovery with two checkpoint spacings, and prints the numbers of shared and unused gates of the generator (14 and 0).

## 2. The attack (program `experiments/bsrho.py`, sections 3 to 6)

Parameters for n = 256: N = 2^256, 256 lanes. A point x is distinguished (a DP) when its low 32 bits are zero and the 90-bit number F = (x >> 32) mod 2^90 is below Tp = 1949. The density is theta = 1949 / 2^122 and L = 1 / theta = 2^111.0715. The key of a DP is the 41 bits of x above bit 121 followed by the 11 low bits of F (F < 1949 <= 2^11, so those 11 bits are F): 52 bits.
One fresh uniform 256-bit word r (one operation). Trail t (t = 0, 1, 2, ...) starts at s_t = r + t mod 2^256 and follows x -> g(x) until a DP.
1. 256 trails run in the 256 lanes: lane l of the bit planes holds the current point of its trail. A batch is one evaluation of g for all 256 lanes by the generated straight line of Section 3.2. Batch counter b = 0, 1, ...; the start of a trail is the point of its lane before the batch in which it was inserted.
2. After every batch the stage-1 test (Section 3.3) ORs the 10 lowest planes. If every lane has a 1 among them (the OR is all ones) the batch ends. Otherwise (the batch passes the checkpoint) it ORs the next planes up to the checkpoints 12, 14, 16, 20 and 32 in turn and ends at the first checkpoint where the OR is all ones; a batch that passes all of them has a lane with all 32 low bits zero, and these lanes are the stage-1 hits.
3. For each hit the lane is extracted and the window test F < Tp decides whether it is a DP. A lane at a DP ends its trail. If its key is in the table, go to 6. Otherwise store t under the key (Section 7) and start trail t' = next index in that lane (insert the 256 bits of r + t' into the lane).
4. At every multiple of S = 2^48 batches: a lane whose trail has age >= c = 20 L batches is restarted with a new index (a cut trail).
5. The search halts (failure) after B batches, after pmax_i batches passing checkpoint i (i = 1, ..., 5: the checkpoints 10, 12, 14, 16, 20), after e2max stage-1 hits, when the table holds tmax = 126,961 keys, when a second trail would be cut, or if step 6 halts or finds no pair.
6. Recovery of the two trails A, B with the same key. Pass 1: both walk together from their starts r + t, r + t' (two lanes of one packed circuit, one step per batch); after each step a lane that has not finished stores its point as a checkpoint when the step number is a multiple of D = ceil(c_r / 8192) and is tested for being a DP; the step at which a lane first is a DP is its length. More than c_r = ceil(12.4 L) steps halts the run. Each trail has at most 8,192 checkpoints, kept in the table region (the table is not needed any more: the run ends with this recovery). Pass 2: let A be the longer trail, d = l1 - l2 >= 0 and A_j, B_j the points after j steps. P(j): A_(j+d) = B_j is false and then true (a merge persists). If the two DP points differ (a key match without a merge) or P(0) holds (the start of B lies on A), there is no pair. Otherwise a bisection over the checkpoint indices i keeps P(lo D) false and P(min(hi D, l2)) true, starting from lo = 0, hi = floor(l2 / D) + 1; a probe of index i loads checkpoint i + floor(d / D) of A, walks it d mod D steps (one lane) and compares with checkpoint i of B. At the end the two lanes walk together from A_(lo D + d), B_(lo D) for at most D steps; at the first step with g(a) = g(b) and a != b the pair (a, b) is output. The packed circuit (609 operations: the compression and one XOR of each of the 8 output words with the 32-bit word of q) evaluates both lanes.
Constants (computed by `plan(256)` of the program from the stated formulas, printed by `python3 bsrho.py --ledger`): Tp = 1949, L = 2^122 / 1949, B = 1324546580108000000000000000000000000, Q = 256 B = 0.99648 * 2^128 evaluations, e2max = 2 B 256 / 2^32 + 64 = 157898256791591644287109375064, pmax_i = ceil((1 + 2^-8) B P_i) + 64 with P_i = 1 - (1 - 2^-k_i)^256 (the probability that 256 uniform lanes pass the first k_i planes; k_i = 10, 12, 14, 16, 20: P_i = 0.221294, 0.0605941, 0.0155040, 0.00389866, 0.000244111): pmax = 294259642401088476963282796482016896, 80573229699097545943031562589001656, 20616031190410319193284089709045503, 5184128763779444449333331772969531, 324599345188758693809558444021692; c = ceil(20 L) = 54560410293890851632788386260865863 (2^115.3934), c_r = ceil(12.4 L) = 33827454382212328012328799481736835 (2^114.7037), D = 4129327927516153321817480405486, table capacity tmax = 126,961 keys in 126,962 slots of 7 bytes. The trail numbers t stay below 2^17 (256 starts, at most 126,961 finished trails, at most 1 cut trail: t <= 256 + 126,961 + 1 < 2^17), so the 17-bit field never overflows (the program asserts LANES + tmax + CMAX < 2^17 in its plan and t < 2^17 when it stores an entry); no length is stored.
Per attempt: one fresh r; no restart, no amplification, no stored collision. The mask q is derived by the generator at setup and is written into the recovery circuit as immediates. The only advice is K.

## 3. Operation ledger

### 3.1 Machine
Machine model declared by this entry (as in 3c2d1220 and 0a9640ed, which passed the judges with it). The benchmark's cost model reads (collision-frontier-v5, `cost_model`): "Classical probabilistic 256-bit word RAM. One selected-round target compression or sponge permutation costs one unit; every other primitive word operation costs 1/C units"; its primitive operations are "256-bit load or store", "addition/subtraction modulo 2^256", "bitwise AND/OR/XOR/NOT", "shift or rotation", "comparison", "conditional branch", "independent uniform random 256-bit word"; its memory includes "code", "working state", "tables". It fixes the word size and prices loads and stores, and it gives no register count.
This entry therefore declares a load/store machine with 256-bit words, 256-bit immediates and R = 800 registers (a declared convention, H3, supporting). Charged: every addition, AND, OR, XOR, shift, comparison, conditional branch and the one random word; every load and every store of a word, one operation each; every register move, one operation each.
The main loop has no loads, stores or moves: the generated straight line needs 773 registers (`allocate` assigns them; output plane j is written into the register that held input plane j, so the next batch reads the same registers), leaving 27 of the 800 for the loop counter, the limit and the handlers' temporaries. The file of 800 registers is counted as memory: 25,600 bytes (Section 7).
Constants are immediates. The organizer's reference count C(r3) = 638 (14 + 208 r) is used only as the unit: Unit = 638 operations. Code is memory, and the cost model does not fix its format; this entry prices it. A gate of the step or of the stage-1 test (XOR, AND or OR of two registers into a register) is one native 32-bit record, charged 4 bytes: a 2-bit opcode (0 XOR, 1 AND, 2 OR) and three 10-bit register numbers (800 registers are below 1,024), the record of c1e9a797. The generator writes exactly these records (Section 3.6). An instruction of the packed recovery circuit is one 40-bit word, charged 5 bytes: an 8-bit opcode and three 10-bit fields. Every other instruction (the compares and branches of the stage-1 test, loop control, handlers, setup, cut and slice, the recovery besides its circuit, and the WebAssembly image of the generator) is charged 36 bytes (opcode, registers and an inline 256-bit immediate). The 4-byte record and the 5-byte word are prices stated by this entry (H3), not measurements.

### 3.2 One batch = 16558 operations for 256 trails
Representation: a 32-bit word is 32 planes; plane j is a 256-bit integer whose bit l is bit j of the word of lane l. A rotation is a renaming of planes (no operation). XOR of words is 32 gates. Constants (the IV words, the prefix words m0..m7, the length and the flag word) are folded at build time. Each signal is a pair (node, polarity): the register holds the node's value and the true plane is that value XOR polarity, so complements are free.
Two-addend sums (`Gen.add`) are a ripple of full adders. The full adder is the pivot adder of 6ae36351 (`Gen.fa`): of three variable inputs two have the same polarity; with the third as the pivot p and the two equal ones x, y: u = x XOR p, sum = u XOR y, carry = (u AND (y XOR p)) XOR p; u and y XOR p have equal polarity, so the AND is one gate (an AND of two upright planes or an OR of two inverted ones): 5 gates. With one constant input k: sum = x XOR y XOR k, carry = x AND y (k = 0) or x OR y (k = 1). For k = 1 and x, y of opposite stored polarity the carry is built as yy OR (x XOR y), yy the operand whose polarity equals that of x XOR y, which reuses the sum's XOR: 2 gates (the constant-bit carry fold suggested by Grok, xAI, checked here by the selftest and the reference comparison). With two constants the plane passes through.
Three-addend sums (`Gen.add3`, the column of 10ce9f59). BLAKE3 computes a = a + b + m twice per G call. When all 96 planes of a, b and m are variable (20 times at three rounds), and at the s3 call 22 (round 1, G call 3, first sum, m = m4 = 0x70000000; the constant ADD3_AT), the three words are added in one ripple; the other sums (the first half of round 0 and every other sum with a prefix word) are partly constant and use two two-addend ripples. In the ripple the three words are added in one ripple whose carry between columns is a pair of planes (u, U) standing for the value U ? 1 : 2u. Bit 0 is a pivot full adder whose carry enters as the pair (0, k). A column takes the three addend bits x, y, z and the incoming pair and returns the sum bit and the outgoing pair, x + y + z + c = s + 2 c':
- template 0: n5 = z ^ U, n9 = x ^ n5, s = y ^ n9, n6 = x ^ y, n8 = U | (z ^ u), n11 = !n6 & n9, u' = n5 ^ n11, U' = n8 ^ n11;
- template 1: w = y ^ U, n8 = z ^ w, s = x ^ n8, n6 = U | (y ^ u), u' = n6 ^ w, U' = n6 ^ ((z ^ w) & (x ^ w));
- form 2: for the four stored-polarity contexts (x, y, z, u, U polarities 16 or 7 in the program's encoding, with or without u') in which both templates need 10 gates, a fixed circuit of AND, OR and XOR gates on the stored planes from an exact synthesis (table `COLLIB` of the program; each checked on all 32 input rows, and by the selftest through the whole step).
For each of bits 1 to 30 the generator builds the six addend orders with the three forms as dry trials (the new gates are removed again) and keeps the first with the fewest new gates; bit 30 builds only U'; bit 31 is s = x ^ y ^ z ^ U (3 gates). At three rounds every all-variable sum costs 5 + 8 + 28 * 9 + 8 + 3 = 276 gates (two two-addend ripples: 308): the census of their 600 columns of bits 1 to 30 is 560 middle columns of 9 gates (403 template 0, 145 template 1, 12 form 2) and 40 boundary columns of 8 gates (24 template 0, 13 template 1, 3 form 2). At call 22 the constant planes of m fold inside the columns (columns of 5, 6 and 7 new gates; 14 template 0, 16 template 1): the sum builds 157 new gates, and 14 of its gates are equal to gates built earlier in the network and are shared, against 159 gates for its two two-addend ripples.
The generator builds the straight line at run time. The reference generator `Gen`/`Step` shares equal gates (hash-consing on the operation and the two operand nodes) and drops unused ones: the selftest prints 14 shared and 0 unused gates, all 14 shared at call 22. The machine generator of Section 3.6 builds the network in two passes with a node table that returns the earlier gate in the same way.
The mask walk: the circuit's 256 output planes are stored in registers exactly as the circuit produces them and are the 256 input planes of the next batch, so no operation complements a plane and the chain is x -> g(x) = f(x) XOR q. Equality under g is equivalent to equality under f (Section 1).
The generated line (`python3 bsrho.py --ledger`, `--selftest`): 16544 gates = 13488 XOR + 1333 AND + 1723 OR = **16544 operations**, no complement operation. Per trail 64.63 operations = 0.1013 unit, against 1 unit for a compression.
The generator runs once at the start of the attempt; its work is charged in the setup row (Section 3.3), its code and peak storage in Sections 3.6 and 7.

### 3.3 Loop, stage 1, handlers and the other events
Loop body = one batch: 16544 + stage-1 test 11 + loop control 3 = 16558 operations. Stage 1 (`stage1`, `stage1_ks`, `stage1_ops`; checkpoints `SC` = 10, 12, 14, 16, 20 and the 32nd plane): the 10 lowest planes of digest word 0 (stored planes, upright: they are the planes of the next point) are ORed (9 ORs), the result is compared with the all-ones immediate and a branch ends the batch when it is all ones: 11 operations. A batch that passes checkpoint k_(i-1) (some lane is zero on its first k_(i-1) planes) ORs the next k_i - k_(i-1) planes into the accumulator, compares it with all ones and branches: 4, 4, 4, 6 and 14 more operations for the checkpoints 12, 14, 16, 20 and 32. A lane is a stage-1 hit when its 32 low bits are zero; the complement of the OR that marks the hits is formed in the hit handler. The test loses no event: a DP has all 32 low bits zero, so its batch passes every checkpoint and its lane is a hit. The batches passing checkpoint k_i (i = 1, ..., 5) are counted and halt the run beyond pmax_i = ceil((1 + 2^-8) B P_i) + 64 (Lemma 2, Step 7); they are charged at the budgets: pmax_1 * 4 + pmax_2 * 4 + pmax_3 * 4 + pmax_4 * 6 + pmax_5 * 14.
Loop control: batch counter increment, compare with the next slice limit, branch back: 3 operations.
Handlers (charged per event at the stated bounds; instruction sequences use the same registers):
- Stage-1 hit: the complement of the mask (1), store the 256 planes to an 8 KiB copy in memory (256 stores), then per plane: load, shift right by the lane number, AND 1, shift left by the plane number, OR into the accumulator, address increment, plane counter increment, compare, branch (9 per plane, 2,304), find the lane in the mask (at most 8 halving steps of 5), window test of F < Tp (3 extractions and at most 12 further operations), counters. Total below 2,800; charged **2,800** per hit. The hit budget e2max is enforced by a halt.
- Finished trail (a DP, new start): key formation, the new start r + t' (1 add), insertion of the 256 bits of the new start in the lane: per plane load, shift, AND 1, shift left by the lane number, AND with the complement of the lane bit, OR, store, address and counter increments, compare, branch (12 per plane, 3,072), reload of the 256 planes (256), lane arrays and counters (below 200). Total below 3,550; charged **3,800**. The table walk is charged separately per slot of the table: a lookup visits at most 3 S slots (the walk back to the start of the cluster, the walk forward over the runs, the scan of the key's run; S = tmax + 1 slots) and an insertion moves at most S entries one slot to the right; the 56-bit slot i lies at bit 56 i and spans at most two words, so a visit is at most 12 operations (offset arithmetic 3, 2 loads, 2 shifts, OR, mask, test, branch, increment) and a move at most 24 (a read and a two-word read-modify-write); charged **64 (S)** per finished trail (3 * 12 + 24 = 60 <= 64). At most tmax finished trails (a halt on a full table).
- Slice check (every 2^48 batches): the 256 births (load, subtract, compare, branch: 1,024), slice counter: charged **1,300** each. Cut trail: insertion of the new start as above plus bookkeeping, charged **4,200**; at most 1 cut trail (a halt on the second).
- Recovery. A pass-1 batch: the packed circuit on two lanes (609 operations, the last 8 of them the XORs with q), then the loop increment, compare and branch (3), call, return and the 8 moves of the digest (10), the DP test of each of the two lanes (low 32 bits: shift, AND, branch; window: shift, AND, compare, branch; 7 per lane, 14), the two finished flags (6), and the checkpoint countdown (decrement, compare, branch: 3): **609 + 36**. A stored checkpoint pair: per lane the 256-bit point is extracted from the 8 packed words (shift, AND, shift, OR per word: 32), stored (1) and its address advanced (1); with the countdown reset, **80** per pair, at most 8,192 pairs. A pass-2 batch: the packed circuit plus the equality test of lane 0 and lane 1 on the 8 output words (8 shifts, 8 XORs, 7 ORs, 1 AND with the lane-0 mask, 1 compare, 1 branch = 26), loop 3, call 2 and 8 moves: **609 + 39** (a single-lane walk of a probe needs no test and is inside the same charge). Pass 2 runs at most 16 single-lane walks of at most D - 1 batches (the probe of P(0), at most ceil(log2(8,193)) = 14 bisection probes, and the walk to A_(lo D + d)) and one joint walk of at most D batches: at most 17 D batches. A probe besides its walk (midpoint, two checkpoint addresses and loads, insertion into lane 0 of the 8 packed words 24, extraction 32, compare, branch, update, loop): below 100, charged **100**, 16 probes. Call, d = l1 - l2, the quotient and remainder of d by D (13-bit quotient), the final walk length and the output: **600**. Pass 1 is bounded by its halt at c_r; pass 2 by the bisection.
- Setup and generator: 1 random word; the 256 starts r + t inserted in memory (256 x 3,100 = 793,600, each at most 12 x 256 + 28) and one reload; counters; fixed part charged 813,600. ### 3.6 Generator code and peak storage of the setup
The generator that builds the straight line at the start of the run is part of the machine code. It is the freestanding C program `GEN_C` embedded in `experiments/bsrho.py` (`python3 bsrho.py --gen-c`). It builds the network of Section 3.2 (pivot adders, the constant-bit carry, the three-addend columns with their dry trials) and allocates the registers in two passes with a node table (2^15 slots of a 32-bit key: operation and the two operand nodes, and a 32-bit signal: node and register; linear probing; cleared at the start of each pass). A gate whose key is in the table is not built: the stored signal is returned, nothing is recorded and no use is counted, as `Gen.mk` shares it. ## 4. Success probability

Heuristic H1 (model premise, Section 5). Let F be a uniformly random function from 256-bit values to 256-bit values and N = 2^256. Write A_F for the procedure with every evaluation of g replaced by an evaluation of F (lazy sampling), and P_F for its success probability over the fresh word r and over F. H1 states that the probability that the single attempt succeeds on the fixed target is at least P_F. The premise compares two success events; it is not a statement about the entropy of r or about the target as a random object, and it is declared, not proved. Lemma 2 below is a theorem about F with no premise: its inputs are Lemma 1 (a statement about g itself) and the lazy-sampling facts of Step 1 (statements about F, exact for the adaptive choices of the program: which trails finish, are cut or abort depend on earlier outputs). H1 enters only in the passage from A_F to the real attempt; its clause (d) (Section 5) says that g has the collision hazard that F has by construction. The numbers below are printed by `python3 bsrho.py --loss` (the function `_lossq`); Appendix A recomputes them with its own copy.

Lemma 1 (a statement about g itself, no premise). Let x != y be evaluated inputs on two different finished trails with g(x) = g(y), both trails of length at most c_r. Both trails continue identically from g(x), so they end at the same DP with the same key and step 6 runs on them. Pass 1 reaches both DPs within c_r steps and keeps the checkpoints. With A the longer trail and d = l1 - l2, P(j): A_(j+d) = B_j holds for j = l2 (the common DP) and, once true, stays true (A_(j+1+d) = g(A_(j+d)) = g(B_j) = B_(j+1)); P(0) is false: if the start of B were A_d, every point of B would be a point of A, and as a finished trail repeats no point, g(x) = g(y) would force x = y. The bisection keeps P(lo D) false and P(min(hi D, l2)) true, so the first j with P(j) true lies in (lo D, min(hi D, l2)], and the joint walk from A_(lo D + d), B_(lo D) reaches it within D steps; the pair returned there is a merge pair: a != b and g(a) = g(b), so f(a) = f(b). The recovery checks equality before it returns. Pass 2 needs at most 17 D batches (Section 3.3).
The key determines F (F < 1949 <= 2^11 and the key holds its 11 low bits), so equal keys of two DPs differ only if their bits above 162 differ. The table returns the stored trail number of a key exactly: the slot of an entry and the run structure give its 16 quotient bits, the slot stores the other 36 (Section 7). The lanes do not interact: the generated step applies the same function to every lane (Section 3.2), so lane l holds g^b of its start after b batches, exactly as a single scalar chain would.
The stage-1 test loses no event: a DP has its 32 low bits zero, so its batch passes every checkpoint and its lane is a hit. A 52-bit key match without a merge ends the run (failure, cost bounded by one recovery).

Lemma 2 (for the random function F; no premise). Let LANES = 256, B batches, Q = 256 B = 0.99648 * 2^128 evaluations numbered t = 1, ..., Q batch by batch and lane by lane inside a batch, b(t) = ceil(t / 256) the batch of t; N = 2^256, theta = Tp / 2^122 = 1 / L, c = ceil(20 L) = 54560410293890851632788386260865863, c_r = ceil(12.4 L), S = 2^48, M = c + S, N' = (1 - theta) N, q = Q / L = 124296.69, tmax = 126,961, CMAX = 1 (the program halts when a second trail would be cut). Pi_m = (1 - 0/N')(1 - 1/N') ... (1 - (m-1)/N') is the probability that m independent uniform values of a set of N' elements are distinct. PP = Q (Q - 1) / (2 N') = 0.49648, H = (Q (Q - 1) / 2 + 2^17 Q) / N' = 0.49648. Let k = 126932 be the least integer with e^-q (e q / k)^k <= 2^-40, n2 = k + 257, p = e^(-c/L) >= (1 - theta)^c, p2(x) = e^(-(x-1)/L) (1 + (x - 1) theta / (1 - theta)) (decreasing for x > 2), p2 = p2(c). Let F be a uniformly random function on 256-bit values and P_F the success probability of the attempt when every evaluation of g is replaced by F (lazy sampling). Then, with no premise,
    P_F >= 1 - P_coll - P_delay - P_own - P_long - P_age - P_rec - P_dist - P_cut - 2^-40 - P_key - P_table - P_tiny,
where
    P_coll = Pi_Q / (1 - k Q / N') = 0.608642124   (the first collision exists),
    P_delay = (1 - k Q / N')^-1 * sum over the bins (a, b] of [0, Q] of (Pi_a - Pi_b) e^(-theta (B - ceil(b / 256))) = 0.001273   (the merged path needs a DP in the batches that are left; 22,000 bins, Step 5),
    P_own = Q L / N' = 8.144e-06   (the first collision is a cycle of its own trail),
    P_long = M Q p (q + 256) / ((1 - p) N') = 4.102e-08   (its partner is on a trail with c evaluations without a DP),
    P_age = PP p2 = 2.149e-08   (the merged trail is too old when it reaches the DP),
    P_rec = 2 PP p2(12.4 L) = 5.481e-05   (one of the two trails is longer than c_r, so pass 1 of the recovery halts; p2(12.4 L) >= p2(c_r)),
    P_dist = PP L (Q + 2^17) / N' = 4.044e-06   (a later collision on the rest of the merged path),
    P_cut = P(Binomial(n2, p) >= 2) + E_S + E_X + E_J2a + E_J2b + E_Y (Step 6) = 1.632e-05, with E_S = Q L / N', E_X = (Q / N') L e^(-(c-2)/(2L)) (2 + (c - 1)/L) + PP p2, E_J2a = Q L H / N' + (Q + 2^17) L PP / N', E_J2b = PP (1 - theta) p2, E_Y = e^(-(c-1)/L) H,
    P_key = C(tmax, 2) / (2^kb Tp) = 1.846e-06, kb = 41,
    P_table = e^-q (e q / (tmax - 59))^(tmax - 59) = 1.3e-12,
    P_tiny = Q 2^17 / N + k^2 L / N' + 255 Q / N' + exp(-300 + (e^5 - 1) H) + 2^-90 (Step 7; it needs 240 M <= Q and 2^10 M <= 2^k_i B P_i for each checkpoint k_i, which hold here).
The numbers are printed by `python3 bsrho.py --loss` (the function `_lossq`); Appendix A gives the bound evaluated in exact rationals and 60-digit decimals with outward rounding: P_F >= 0.39000000100019 >= 0.39 (the program's float value, planned at the target 0.390000001, is 0.390000001). The program's B is the least multiple of 10^24 for which the float bound reaches 0.390000001. H1 (Section 5) is the only premise of this entry: it states that the real attempt succeeds at least as often as A_F.

Proof.
Step 0 (notation). A trail is the run of evaluations of one lane between two restarts; a(t) is the number of earlier evaluations of the trail of t (its age); the length of a trail is its number of evaluations. A trail is finished when an evaluation returns a distinguished point (DP; that evaluation is its last), cut when a slice check restarts it at age >= c, open when the halt comes first. Every length is at most M, and a trail of length at most c is never cut. An evaluation is fresh when its input has not been evaluated before. A collision is a fresh evaluation whose value equals an earlier value (an earlier output or a start). The starts r + t' (t' < 2^17) differ from every value the run produces except with probability Q 2^17 / N (r is uniform and independent of F); this event is excluded below and charged in P_tiny, so a non-fresh evaluation exists only after a collision on its trail.

Step 1 (lazy sampling with a lottery). Realise F by independent uniform values V_1, V_2, ...: the t-th evaluation returns V_t if it is fresh and the value stored for its input otherwise. This is the lazy sampling of F for every adaptive choice of the points. Put xi_t = 1 when V_t is a DP. The xi_t are independent Bernoulli(theta), one per evaluation index, fresh or not; given all of them the V_t are independent and uniform on their class (the theta N DP values, or the N' other values). Index t belongs to lane (t - 1) mod 256, and the lane positions of a lane are its indices in increasing order; the lottery is extended beyond Q by further independent draws (used in the proof only). G_t is the history of the first t evaluations together with the whole lottery; F_t is the history of the first t evaluations together with xi_1, ..., xi_t only.
(L1) If t is fresh and xi_t = 0, then P(V_t = v | G_(t-1)) = 1 / N' for every non-DP value v (and 0 for DP values), and the events for different v are disjoint.
(L2) Whether t is fresh, its input, its batch, its age and the trails before t are determined by G_(t-1).
(L3) The lottery of a lane is i.i.d. Bernoulli(theta); the lanes are independent. Scanning the lanes one after the other, a scan that takes from each lane a number of positions that is a stopping time of that lane (with further independent coins after the run) reads one i.i.d. Bernoulli(theta) sequence.
(L4) N1 = xi_1 + ... + xi_Q is exactly Binomial(Q, theta), so P(N1 >= k) <= e^-q (e q / k)^k <= 2^-40 (Chernoff: the binomial moment generating function is below the Poisson one); P(N1 >= k) is charged once, as 2^-40.
(L5) The run up to evaluation t is F_t-measurable (it depends on V_1, ..., V_t only, and V_s depends on xi_s and an independent uniform). If s is a stopping time of (F_t), the lottery after s is independent of F_s and i.i.d. (strong Markov property of an i.i.d. sequence).

Step 2 (the free run and the first collision). Given the whole lottery xi, the free run is the run in which every evaluation is fresh: the trail boundaries (a DP at every xi = 1, a restart of a trail of age >= c at a slice check), the ages a(t), the lengths and the batches are functions of xi alone, and so are the sets of long trails (a trail is long when its first c coins are all 0, i.e. when it has c evaluations without a DP; the other trails are short, of length at most c, and are never cut) and the numbers rho(y) = the number of evaluations of the lane of y after y up to and including the first with xi = 1. Let n0(t) be the number of s <= t with xi_s = 0. Let tau be the first t with xi_t = 0 whose value V_t equals V_y for some y < t with xi_y = 0 (the first collision of the non-DP class), E1 the event that a start equals a value of the run (Q 2^17 / N), E2 the event that some DP-valued evaluation equals an earlier DP value (on N1 <= k - 1 its probability is at most k^2 L / N': a DP-valued evaluation is uniform on the theta N DP values, at most k - 1 earlier DP values exist, and there are at most k - 1 such evaluations). Outside E1 and E2 the real run is the free run up to tau (every evaluation is fresh), and until then the non-DP values are independent uniform on the N' non-DP values (L1). Hence, for t with xi_t = 0 and y < t with xi_y = 0,
    P(tau = t, V_t = V_y | xi) = Pi_(n0(t) - 1) / N',    sum over y of that = Pi_(n0(t)-1) - Pi_(n0(t)),    P(tau <= Q | xi) = 1 - Pi_(n0(Q)).
On N1 <= k - 1, n0(t) - 1 >= t - k, and Pi_(t-k) <= Pi_(t-1) / (1 - kQ/N') for t <= Q (Pi_(t-1) = Pi_(t-k) times at most k - 1 factors that are each at least 1 - Q/N'; Pi_m = 1 for m <= 1). Pi_m is bounded by exp(-m (m - 1) / (2 N')) from above and by exp(-m (m - 1) / (2 N') - (m - 1) m (2m - 1) / (6 N'^2)) from below (ln (1 - x) >= -x - x^2 for 0 <= x <= 1/2).

Step 3 (a first collision with a good partner is output). Say that the pair (t, y) with tau = t and V_t = V_y is good when (G1) y is not on the trail of t, (G2) b(y) < b(t), (G3) the trail of y is short, (G4) rho(y) <= B - b(t) and a(t) + rho(y) <= c - 1, (G5) a(t) + rho(y) <= c_r - 1 and a(y) + rho(y) <= c_r - 1, and that it is undisturbed when no fresh evaluation of the trail of y after t, up to its first DP, is a collision. Claim. On a good undisturbed pair, if the run does not halt early (second cut, table full, stage-1 or passing-batch budget, key false match) and is outside E1 and E2, the program outputs a pair. Proof. Let X and Y be the trails of t and y. The input of X after t is V_t = V_y, the input of Y after y, so the evaluations that X performs after t are the evaluations Y performs after y, the j-th of them in batch b(t) + j for X and in batch b(y) + j for Y (Y does not restart before its DP, because its trail is short, hence never cut, and its first DP is the (rho(y))-th evaluation after y). By (G2) Y evaluates each of them strictly before X, so X only repeats points (they are not fresh). Undisturbed: the evaluations of Y after t are fresh and not collisions (those before t are not collisions, tau being the first), so the lottery of the lane of Y decides the DP: Y ends with a DP at its rho(y)-th evaluation after y, in batch b(y) + rho(y) < b(t) + rho(y) <= B (G4), inside the run, and the key of the DP is stored (the table is not full). X repeats it in batch b(t) + rho(y) <= B with the same DP and the same key; X has then done a(t) + rho(y) + 1 <= c evaluations, so no slice check cut it (a slice check cuts a trail of age >= c, and the age before its last evaluation is a(t) + rho(y) <= c - 1). The two trails are different (G1), finished, with the same key, of lengths a(t) + 1 + rho(y) and a(y) + 1 + rho(y), both at most c_r (G5), and the inputs of t and of y are different (t is fresh) with g(t) = g(y): Lemma 1 applies. QED.

Step 4 (the pairs that are not good, and the disturbance). Let W(t, y) be the event (tau = t, V_t = V_y) with xi_t = xi_y = 0 and work on N1 <= k - 1 outside E1 and E2. By Step 2, P(W(t, y) | xi) <= Pi_(t-1) / ((1 - kQ/N') N') <= 1 / ((1 - kQ/N') N'), and sum over t of P(W(t, y) | xi) is at most the sum over t of 1 / N', so at most Q / N'. A pair that is not good fails one of the following; each failure is bounded by the expected number of pairs of that kind times the hazard.
(a) (G1) fails: y is among the a(t) earlier evaluations of the trail of t; a(t) is at most g(t), the number of consecutive 0 coins just before t on its lane (g(t) as in Step 6 (ii)), E g(t) <= sum over i >= 1 of (1 - theta)^i <= L - 1, so the failure has probability at most Q L / N' = P_own.
(b) (G2) fails: y is in the batch of t before t, at most 255 pairs per t: 255 Q / N' (charged in P_tiny).
(c) (G3) fails: y is on a long trail. A long trail has at most M evaluations (it is cut at the first slice check at age >= c, or finishes before), a y has at most Q partners t, and the number of long trails is at most the number of successes of the scan of Step 6 (i) (disjoint windows of c coins 0), with expectation at most p (q + 256) / (1 - p) there: M Q p (q + 256) / ((1 - p) N') = P_long.
(d) (G4) fails. rho(y) > B - b(t) means that the B - b(t) coins after y on its lane are all 0 (they lie in the batches b(y) + 1, ..., b(y) + B - b(t) <= B, inside the run), probability (1 - theta)^(B - b(t)) <= e^(-theta (B - b(t))) for each y. By Step 2 the pairs (t, y) with y < t contribute at most sum over t of (t - 1) Pi_(t-1) / ((1 - kQ/N') N') e^(-theta (B - b(t))), and (t - 1) Pi_(t-1) / N' = Pi_(t-1) - Pi_t, so, with b(t) <= ceil(b / 256) for t <= b and the sum of Pi_(t-1) - Pi_t over t in (a, b] equal to Pi_a - Pi_b, at most (1 - kQ/N')^-1 sum over the bins (a, b] (Pi_a - Pi_b) e^(-theta (B - ceil(b / 256))) = P_delay (the bins and the enclosures of Pi are in Appendix A). The second part, a(t) + rho(y) >= c: a(t) <= g(t) and rho(y) >= 1, so it requires g(t) + (rho(y) - 1) >= c - 1. If t and y are on different lanes the two coin sets are disjoint and g(t), rho(y) - 1 are dominated by independent geometric variables with values in 0, 1, 2, ...; the sum of two such variables is at least c - 1 only if a single i.i.d. sequence of coins has at most one 1 among its first c coins, hence among its first c - 1 coins: probability at most (1 - theta)^(c-1) + (c - 1) theta (1 - theta)^(c-2) <= p2. If they are on the same lane and (G1) and (G3) hold, y is on an earlier trail of the lane that is short, so it ended with a 1 before the start of the trail of t, and the two coin sets (those of rho(y) up to that 1, those of g(t) after it) are disjoint: the same bound. At most Q (Q - 1) / 2 pairs, each with hazard at most 1 / N': PP p2 = P_age.
(f) (G5) fails. The first part, a(t) + rho(y) >= c_r, is the second part of (d) with c_r in place of c: probability at most p2(c_r) per pair. The second part, a(y) + rho(y) >= c_r: the evaluations of the trail of y up to y are fresh and not DPs, so a(y) <= g(y), and xi_y = 0; the g(y) coins 0 before y, the coin of y and the rho(y) - 1 coins 0 after it form a run of 0s of length at least c_r, and the coins before and after y are disjoint and dominated by independent geometric variables, so the probability is at most p2(c_r) as in (d). At most Q (Q - 1) / 2 pairs, each with hazard at most 1 / N': 2 PP p2(c_r) <= 2 PP p2(12.4 L) = P_rec.
(e) Disturbance. For a good pair let r' be the number of evaluations of the lane of y with index > t up to and including the first with xi = 1; the coins there are independent of F_t (L5, t is a stopping time) and r' is dominated by a geometric variable of mean L. The evaluations of Y after t and before its DP are at most r' fresh evaluations, each a collision with conditional probability at most (Q + 2^17) / N' given the history (L1; the last one, a DP-valued evaluation, is covered by E2, and counting it here only overcounts). For this bound W(t, y) is taken without the restriction to N1 <= k - 1 and outside E1, E2: it is the event (tau = t, V_t = V_y), which is F_t-measurable, so P(W(t, y) and disturbed) <= P(W(t, y)) L (Q + 2^17) / N'; the events W(t, y) for different (t, y) are disjoint (the values V_y are distinct before tau), so the sum of P(W(t, y)) is at most P(tau <= Q) <= sum over t of (t - 1)/N' = PP: PP L (Q + 2^17) / N' = P_dist.

Step 5 (the sum). With P(tau <= Q, N1 <= k - 1) >= 1 - Pi_(Q-k+1) - 2^-40 >= 1 - P_coll - 2^-40 (Pi_(Q-k+1) <= Pi_Q / (1 - kQ/N'): n0(Q) >= Q - k + 1 on N1 <= k - 1 and Pi decreases) and Step 3, the attempt succeeds unless one of the failures (a) to (f) occurs for the first collision, or E1, E2, N1 >= k occur, or the run halts early: P_F >= 1 - P_coll - 2^-40 - P_own - P_long - P_delay - P_age - P_rec - P_dist - 255 Q / N' - P(E1) - P(E2) - P(early halt). The early halts are charged in Step 6 (second cut) and Step 7 (table full, key false match, stage-1 and passing-batch budgets).

Step 6 (the cut count and the long trails; no premise). Let K be the number of trails that the run cuts or would cut (the second one halts the run). Split K = K_A + K_B: K_A counts the cut trails whose first c evaluations are all fresh, K_B the others.
(i) K_A. A trail counted by K_A has c fresh evaluations with non-DP outputs at c consecutive positions of its lane, so xi = 0 there; different such trails of a lane use disjoint positions. Scan each lane with trials: a trial starts at the current position u and succeeds if the c positions u, ..., u + c - 1 are all 0 (next trial at u + c); otherwise it fails at its first 1 (next trial after that 1). The scan of a lane stops at the first trial that would start after the run. Inside a maximal run of 0s the trials start at its first position and succeed floor(length / c) times, the largest number of disjoint length-c windows it holds; so K_A on a lane is at most the successes on that lane. Every failure but the last of a lane ends at a 1 of the run, so the failures are at most N1 + 256 <= k - 1 + 256 on N1 <= k - 1. Trial outcomes are independent Bernoulli(p'), p' = (1 - theta)^c <= p = e^(-c/L) (disjoint positions of an i.i.d. lottery; lanes concatenated as in (L3)). All successes therefore occur before failure number k + 256 of an infinite i.i.d. trial sequence, and two successes before that failure mean two successes among the first n2 = k + 257 trials:
    P(K_A >= 2, N1 <= k - 1) <= P(Binomial(n2, p) >= 2) = 1 - (1 - p)^n2 - n2 p (1 - p)^(n2 - 1)
(the tail increases with p, so p = e^(-c/L) is allowed).
The same scan counts the long trails of Step 2: a long trail of the free run is a window of c coins 0 at its start, the windows of different trails of a lane are disjoint, and a run of 0s holds at most floor(length / c) disjoint windows, which is what the scan finds; so the number of long trails is at most the number S_c of successes. The trial outcomes form one i.i.d. Bernoulli(p') sequence read in a stopping-time order (L3), so Wald's identity gives E S_c = p' E T, T = S_c + F_c the number of trials, with F_c <= N1 + 256 the number of failures, E F_c <= q + 256: E S_c <= p (q + 256) / (1 - p) (used in Step 4 (c)).
(ii) K_B. A trail T in K_B has a first non-fresh evaluation at age <= c - 1. Its previous evaluation t (age a(t) <= c - 2, T fresh up to t, so a(t) <= g(t), where g(t) is the number of consecutive 0s of the lottery just before t on its lane) is fresh, and V_t equals the input of an earlier fresh evaluation e' (the first evaluation of that input; a start is excluded). Call t the joining collision of T and e' its target. For a lane position e let sigma(e) be the number of positions from e to the first 1 at or after e (inclusive), and f'(e) that position: sigma is a function of the lottery, so it is determined by G. Choose T in K_B with the earliest joining collision. One of the following root events occurs:
- S: e' is on T itself. T then cycles through its own non-DP points and is cut.
- X: e' is on another trail T' and a(t) + sigma(e') >= c (hence g(t) + sigma(e') >= c).
- J2a: e' on T', a(t) + sigma(e') <= c - 1, and T' has a collision at a fresh position in [e', f'(e')).
- J2b: e' on T', and e' lies in a run of 0s of length >= c of its lane.
- Y: some trail has a collision at a fresh evaluation t'' while it has been fresh for at least c - 1 evaluations (g(t'') >= c - 1).
Proof that one occurs. Suppose not S, X, J2a. T evaluates the inputs evaluated by T' from e' on, one batch later or more, so T repeats them (non-fresh) while T' is ahead. If T' evaluates e', e' + 256, ..., f'(e') freshly (no collision there by not-J2a, and every non-fresh evaluation of T' is preceded by a collision of T'), the output at f'(e') is a DP (fresh, xi = 1), and T outputs the same DP at age a(t) + sigma(e') <= c - 1, before any slice check can cut it: T is not cut, a contradiction. If the run ends first, T, which is behind, is not cut either. So T' is cut before f'(e'), with all its evaluations from e' to the cut fresh. If all evaluations of T' from its start to the cut are fresh, they are >= c consecutive 0s containing e': J2b. Otherwise T' has a non-fresh evaluation before e', hence a joining collision before e' and before t; if it is at age <= c - 1, T' is in K_B with an earlier joining collision than T, against the choice of T; if not, the first c evaluations of T' were fresh and T' collided at age >= c - 1 while fresh: Y. QED.
Expected numbers of root events, each from the hazard (L1) (a collision of t with a given earlier value has conditional probability at most 1 / N' given G_(t-1), which includes the lottery, so lottery conditions can be attached):
- S: the inputs of T before and at t are a(t) + 1 <= g(t) + 1 values; E[g(t) + 1] <= sum for i >= 0 of (1 - theta)^i = L, so E_S <= Q L / N' = 8.144e-06.
- X: E_X <= sum over pairs e' < t of P(sigma(e') + g(t) >= c) / N'. Different lanes: sigma(e') - 1 and g(t) are independent and dominated by geometric variables on {0, 1, ...}, so the probability is at most P(at most one 1 in c - 1 Bernoulli trials) = (1 - theta)^(c-1) + (c - 1) theta (1 - theta)^(c-2) <= p2. Same lane, e' = t - j 256: if a 1 lies between them the two runs of 0s are disjoint and the same bound p2 holds; if the j positions are all 0, the probability is at most (1 - theta)^j T(c - 1 - 2j) with T the tail above (T = 1 below 1); the sum over j of these is at most L e^(-(c - 2)/(2L)) (2 + (c - 1)/L). Hence E_X <= (Q / N') L e^(-(c-2)/(2L)) (2 + (c-1)/L) + PP p2 = 2.963e-08.
- J2a: two collisions, t (joining onto e') and t' on T' at a position in [e', f'(e')). If t' < t: for a given t', the e' with t' in [e', f'(e')) on the same lane are at most g(t') + 1, so the targets of t are at most the sum over collisions t' < t of g(t') + 1, and E_J2a1 <= Q L H / N'. If t' > t: the positions in the windows [e', f'(e')) of earlier joining targets number at most the sum of sigma(e') over collisions t, with expectation at most L Q (Q - 1) / (2 N') (E sigma = L), and each such position is a collision with probability at most (Q + 2^17) / N': E_J2a2 <= (Q + 2^17) L Q (Q - 1) / (2 N'^2). E_J2a = 8.087e-06.
- J2b: P(e' lies in a run of 0s of length >= c) <= (1 - theta) p2 (the 0s before and after e' are dominated by two independent geometric variables), so E_J2b <= PP (1 - theta) p2 = 2.149e-08.
- Y: P(g(t'') >= c - 1) <= (1 - theta)^(c - 1) <= e^(-(c-1)/L), times the collision hazard summed over t'': E_Y <= e^(-(c-1)/L) H = 1.023e-09.
So P(K >= 2) <= P(K_A >= 2, N1 <= k - 1) + P(N1 >= k) + P(K_B >= 1) <= P(Binomial(n2, p) >= 2) + E_S + E_X + E_J2a + E_J2b + E_Y + [P(N1 >= k), charged once as 2^-40]; P(Binomial(n2, p) >= 2) = 3.308e-08 and P_cut = 1.632e-05 (the program's `cut_halt`). There is no premise about K: the number of cut trails is bounded by this argument, and it needs no distribution of K. The bounds on S and J2a are not small (about Q L / N' each); they are the real cost of trails that close a cycle or join a path that is itself disturbed.

## 5. Premise H1 and its evidence

H1 is the model premise of Section 4. It is a premise about one fixed function g and about one attempt; it cannot be tested at width 256: the full 256-bit functional graph, trails longer than 2^40 and 2^128 evaluations cannot be observed. It is declared and not proved: an assumption, no proof is known. Its content, in the terms Lemma 2 uses, is four clauses: (a) for the inputs the search evaluates, the outputs behave as the outputs of F, uniform and independent, so that two distinct evaluated inputs collide with probability 2^-256 (this entry uses no input difference and does not claim that none exists); (b) the iterates of g from the starts r + t have the first-collision law of a random mapping; (c) whether an iterate is a DP is independent of the collision events and has probability 1949 / 2^122; (d) adaptivity: the program chooses its points, and which trails finish, are cut or abort, from earlier outputs of g; clause (d) is that this adaptivity does not lower the collision hazard, that is, for every fresh evaluation, given the whole history of the run and which later outputs are distinguished points, the output equals a given earlier non-distinguished output with probability at least 2^-256 (the lazy-sampling hazard that F has by construction, L1 of Section 4). Lemma 2 proves the bound for F from the hazard alone (the first collision of the run and the detection delay, no conditioning on which trails finish), and (d) is the premise that g has that hazard. The prefix K and the mask q fix the function g; H1 is stated for this g. Nothing else in the success bound is heuristic: Lemma 1, the lazy-sampling facts, the first-collision bound, the Chernoff bounds, the budgets and the cut count are proved in Section 4 for F; Sections 3 and 7 are counts of the program. Sensitivity: a hazard (1 - eps) / N costs the same as a deficit eps in clause (a): 0.0073 bit for eps = 0.01, 0.0370 bit for eps = 0.05, 0.0760 bit for eps = 0.10, 0.2075 bit for eps = 0.25 (Section 4).
The two organizer experiments (Section 6) check that the program is right on the real target: the organizer recomputes every returned pair. They are program checks, reproducible observations consistent with the premise; no number of this entry is estimated from their counts, no interval is formed, and the entry does not rely on the independence of trials.
At width 18 a halt "recovery found no pair" (a trail start lying on another trail) is frequent; at width 256 it has probability below 2^-100 (Section 4). It happens equally for the ideal function.
Not tested: the full 256-bit functional graph; iterations of length above 2^40; the bit-sliced search above width 18. A deviation of g from H1 that raises the collision rate only helps; one that lowers it by eps costs the extra time above.

## 6. Experiments

Two organizer experiments run the shipped program `experiments/bsrho.py` (it dispatches on the experiment id; the standard library only).
`bsrho-n18`: per trial, from the trial seed, one attempt of the 256-lane search at width n = 18 (DP = low 2 bits zero, plan(18): 8 batches, the stage-1 test, the quotient-filter table, the cut rule, the recovery with checkpoints on the packed circuit) on the target chain g (the block K || x, the low 18 bits of g); the trial returns the two 64-byte messages K || x, K || y when the attempt succeeded and two nulls otherwise. The checked event is that the complete 3-round digests agree in the low 18 bits and the messages are distinct. Observations (untrusted): the same attempt on an ideal function, and one family-law run with a fresh key at n = 12.
`proj-k0-w256`: per trial, 2048 points of the target at width 256 evaluated with the bit-sliced circuit (source by trial index mod 3: uniform inputs, counter inputs r + i, iterates of g), returning two points whose digests agree in the low 21 bits when the set contains such a pair. The digests are recovered from the stored planes by XOR with q. The checked event is that the digests agree in the low 21 bits and the messages are distinct. Observations (untrusted): the source and the number of equal pairs in the low 21 bits.
They check the circuit at full width, the bit-sliced search, lane insertion and extraction, the table, the recovery, the mask q and the message construction with the prefix K on the real target. They do not measure the cost or the success probability at width 256. Running times on the development machine for 256 trials: 3.5 s and 5.1 s.

## 7. Memory

Table: 126,962 slots * 7 bytes = 888,734 bytes (the table region is empty until the search starts). It is a quotient filter (Bender et al., VLDB 2012; the stored key bits implied by the slot as in eprint 2011/387 Section 2 and 2017/581): S = tmax + 1 = 126,962 slots, l = floor(log2 S) = 16. The 52-bit key is split into the quotient (its top 16 bits), which is the home slot, and the remainder (36 bits). A slot holds 56 bits: the remainder, the 17-bit trail number t and three bits (occupied: some stored key has this home slot; continuation: the entry continues the run of the slot before; shifted: the entry is not in its home slot). The entries of one quotient form a run; runs lie in quotient order, shifted right cyclically past used slots; a lookup walks back to the start of the cluster and forward one run per occupied home slot to the key's run and scans it, an insertion places the new entry at the end of its run and moves the following entries up to the first empty slot one slot right (class `QF` of the program, `find` and `put`; the selftest compares it with a dictionary). At most tmax = 126,961 keys are stored (a halt on a full table), so a slot is always empty and every walk ends. No length is stored (a length is at most c_r and is recomputed by pass 1 of the recovery).
Code: 16,575 gate records * 4 bytes (the step 16544, the 31 ORs of stage 1) + 609 recovery-circuit words * 5 bytes + 1,345 other instructions * 36 bytes (loop control 3, the compares and branches of the 6 stage-1 checkpoints 12, handlers 1,060, recovery besides its circuit 110, setup, cut and slice 160) = 66,300 + 3,045 + 48,420 = 117,765 bytes.
Counters and copies: 16,384 bytes (trail numbers, birth batches, counters, and the 8,192-byte copy of the 256 planes used by the handlers). The 800 registers: 25,600 bytes. Advice K: 32 bytes. Memory peak = max(setup phase 503,027, search phase 1,048,515) = 1,048,515 bytes = 2^19.99992, 61 bytes under 2^20; the preprocessing is inside the setup phase. Claim `memory_log2_bytes` = 20 (the log2 of the 2^20-byte budget); the scalar policy adds 0 (Section 3.8). `python3 bsrho.py --ledger` prints the total. During the recovery the checkpoints (at most 2 * 8,192 points of 32 bytes = 524,288 bytes) are written into the table region, which the run no longer needs (the program asserts 8,192 * 64 <= 7 (tmax + 1)).
The table size is the largest that fits: tmax = floor((1,048,576 - 64 - 117,765 - 25,600 - 16,384 - 32) / 7) = 126,961, and the extra slot comes out of the 64 bytes. Tp = 1949 is the largest integer for which the success bound of Section 4 reaches 0.39 at the largest mean number of trails that the table holds with capacity tail below 2^-40.
