# VOL44: a counted cost bound for a 44-step SHA-256 ordinary collision

Score (collision-frontier-v5): time_log2 = 256.27877 target-compressions. Memory is reported separately: 2^19.89 bytes by construction (complete under the model; term max(0, log2-20) = 0).

## 1. Target and prices
- Target: two distinct messages under the standard IV, the first 44 steps, standard padding and feed-forward, all 256 output bits equal. Each message is one 64-byte data block followed by the common SHA-256 padding block; the two data blocks give an equal chaining value, so the equal padding block preserves the collision and the full messages collide.
- Prices: one 44-step target compression is one unit. Realization on the model's 256-bit word RAM: the bit-sliced state is native (one plane of 256 lanes = one 256-bit word; a gate on 256 lanes = one word operation); every 32-bit word-level value (counters, the control lanes' words, the per-lane recognition words) occupies one 256-bit word of its own, so no extraction or insertion is needed and loads and stores are the ones already charged (x 4); the 7 lists are packed 8 values per 256-bit word and every list read is charged an index add (table index, 1) plus an extraction of 2 operations (shift, mask), itemized in the support work of Section 2. Every other primitive word operation (add, sub, xor, and, or, not, shift, rotate, compare, random word, table index) costs 1/C, with C = 3232. C = 3232 is the organizer reference operation count of the 44-step compression (hash-smash/scripts/reference_operation_costs.py counting method run at 44 rounds; it gives 2896 at 40 rounds).

## 2. Head (experiment v44-shift-01)
- Generator: the VOL40 v7e generator with the W13 retry count raised from 14 to 22 outputs message pairs whose expanded difference follows the msb17 body (difference silent on words 27..39).
- Shift: each pair is replaced by its schedule words -4..11, computed backward from the expansion rule (W_-1 = W15 - sigma1(W13) - W8 - sigma0(W0), and so on to W_-4). The resulting words 0..15 are each member's complete 64-byte data block (equal length; standard padding appends the same final block to both); both are run from the standard IV through all 44 steps using the unmodified SHA-256 schedule recurrence and constants K_i at their original indices i (no step, word, or constant is renumbered), so the claimed event is an ordinary collision of two complete messages. The expansion of the shifted pair is the original expansion moved by 4 words, so the difference is silent on words 31..43 for every generated pair (forced by the construction, Section 3 P2 derivation; checked by the schedule control on the first 16 kept pairs of every batch and on every kept pair of the 200-batch evidence run).
- The generator, the shift, the expansion and the recomputation of the shifted pair from the standard IV work bit-sliced on 256 lanes; a gate on 256 lanes counts as one word operation, the accounting of the board's R40 entry df1f1cd1. Early abort: 4 steps before the junction the batch checks a 32-bit necessary condition that needs only half of the next step (the output a - e of a step equals T2 - d, so the two members must differ there by exactly 2^31); a batch with a live lane then computes that step and checks the register-a and register-e differences (64 bits per lane, counted).

Each word operation is charged together with its two operand loads and one result store (the data-movement upper bound of a register-free RAM program under collision-frontier-v5), so the charged total before the discard factor is 1,950.618 x 4 = 7,802.5 operations per kept pair, and 7,810.3 after it.

## 4. Ledger
- Fixed batch count: B = ceil(N / (212 x (1 - 0.001))) batches, N = ln(1/0.61) x (1 + 2^-6) x 2^256 kept pairs (the factor 1 + 2^-6 covers repeated draws, Distinct pairs below, and the discard tail). Every batch is charged at the declared generation budget 183,864 plus recognition of all 256 lanes (199 each = 50,944) plus the per-batch control block CTRL = 13,500 (controls and tail on the first kept lane, the per-bit tally on the first kept lane, the best-lane output) plus the support work SUPPORT = 165,223 (Section 2, itemized), whether a lane is kept or not and whether the batch is kept or discarded: T = B x (183,864 + 256 x 199 + 13,500 + 165,223) x 4 / 3232 + 4 + 2^30.1, a deterministic total-work bound. Per kept pair this is (183,864 + 50,944 + 13,500 + 165,223) / 212 = 1,950.618 word operations, x 4 loads/stores = 7,802.5, x 1/(1 - 0.001) = 7,810.3 charged operations = 2^1.27295 units. The shipped program runs the per-lane block only on kept lanes, so its executed work is below this charge.
- Distinct pairs: every pair is drawn as follows (tail44_sl.py): the six free message words 0, 1, 2, 3, 9 and 14 are uniform 32-bit draws (192 bits); the seven list words are uniform draws of an index into L4 (1,024), L5 (128), L6 (44), L7 (4), L8 (1,024), L10 (1,024) and L12 (1,024), 2^54.5 equiprobable combinations; each lane's W13 is chosen among at most 32 candidate values that are all determined by the lane's own uniform 32-bit draw (the TRY = 22 retry rounds translate that candidate and the lane keeps the first one that passes the W13 test), so a given W13 value is chosen by a lane with probability at most 32 x 2^-32 = 2^-27, whatever the pass set of its context. Two lanes of the same batch share the free and list words and differ only in W13, so they coincide with probability at most 2^-27; two pairs of different batches coincide with probability at most 2^-192 x 2^-54.5 x 2^-27 = 2^-273.5. Over the run of about 2^247.3 batches of 256 lanes (N = 2^254.98 draws) the expected number of repeated draws is at most 2^247.3 x 32,640 x 2^-27 + N^2 / 2 x 2^-273.5 < 2^235.3 + 2^235.5 < 2^236.5, a fraction 2^-18.5 of N; by Markov's inequality the repeated fraction exceeds 2^-7 with probability at most 2^-11.5. A repeated pair has the same landing event as its first copy and is not a new opportunity, so the success bound counts distinct pairs only: N carries the factor (1 + 2^-6) > 1 / (1 - 2^-7), and the 2^-11.5 bad event is subtracted below. Every list index (nine draws per batch: seven base words, the W17 target and the W25 target) is drawn by a bounded rejection loop in the shipped program (_bdraw): a k-bit draw, k the bit length of the list size, is accepted if it is below the list size and redrawn otherwise, at most 32 attempts, after which the last draw reduced modulo the list size is used. The ledger charges the worst case, 9 x 32 x 3 operations (draw, compare, branch) = 864 operations per batch, included in the generation budget above; the fallback is taken with probability at most 2^-32 per draw and yields a valid list element, so the time bound is deterministic.
- Landing-dependent discards: of the discard rules, only the k4 band (landing_k4 <= kept/16 + 6 sqrt(kept/16), checked over all kept lanes) depends on landing outcomes; the floor, the budget and the hard checks do not. A lane whose pair lands exactly also matches 4 prefix bits, so its batch is discarded only if the other kept lanes alone bring the k4 count to the band's edge. Under P1 and P3 the other lanes' 4-bit matches are independent Bernoulli(1/16) indicators, so with kept >= 212 the probability of that, given the exact landing, is at most Pr[Bin(255, 1/16) >= 34] < 2^-13 (Chernoff). An exactly landed pair is therefore counted as an opportunity with probability at least 1 - 2^-13, which the factor (1 + 2^-6) in N covers together with the repeated draws (2^-7 + 2^-13 < 2^-6 / (1 + 2^-6)); the 2^-11.5 Markov event is subtracted below.
- Discard rate: measured 0 of 200 batches (none under the floor, none at the budget, no hard-check failure; every failed check discards the batch and is in this count); over the 20,000 fresh-seed batches of the shipped program: 0 discarded (none under the floor, none at the budget, no hard-check failure). The declared per-batch discard probability is p <= 2.5e-4 (premise H-kept-pair-yield; the shipped program's 0 discards in 20,000 batches give the one-sided bound 2.31e-4 at alpha 0.01, the organizer's alpha, below the declared value); the declared fraction 0.001 is 4 times p; with B about 2^247.3 independent batches, Pr[more than 0.001 B discarded] < exp(-B x D(0.001 || 2.5e-4)) < 2^-1000 (D = 0.00063 nats per batch), included in the 0.39.
- T = N x 2^1.27295 + 4 x (pairs found).
- log2 N = 256 + log2(ln(1/0.61)) + log2(1 + 2^-6) = 255.00585; log2 T = 256.27877 (exact 256.27876333, rounded up to five decimals).
- Success: under P1-P3 the conditional probability, given that at most a 0.001 fraction of the B batches is discarded, is at least 1 - exp(-ln(1/0.61) x (1 + 2^-6) x (1 - 2^-7 - 2^-13)) > 0.39 + 0.0022 (distinct pairs only, when at most a 2^-7 fraction of the draws repeat, which holds except with probability 2^-11.5, and with the k4-discard loss of at most 2^-13 per landed pair; Distinct pairs and Landing-dependent discards above); subtracting the probability of the bad event (below 2^-1000, Section 4) and the 2^-13.5 repeat bad event leaves an unconditional success probability above 0.39 (0.39 + 0.0022 - 2^-11.5 - 2^-13 - 2^-1000 > 0.3915). The factor (1 + 2^-6) in N adds 0.02240 to log2 T. The run stops at the first found pair; its verification (4 reduced compressions) and the preprocessing 2^30.1 are added to T; neither changes the rounded exponent.
- Hard-asserted checks (tail44_sl.py:302-311): on every organizer trial the shipped program asserts, and fails the trial otherwise: schedule control = one pass per control lane (16 on the first 16 kept lanes in the evidence experiment v44-controls-01, 1 in the charged run; 40-word and shifted 44-word); sliced control = one pass per control lane on those lanes (J26 state and J30); the sliced control also requires the word-level junction difference of each control lane to equal its transposed sliced difference; forced-target tail = 16 and negative control = 0 on those lanes (shifted 30..43 and unshifted 26..39); kept >= 212; generation within its budget 183,864; every one of the 256 J30 junction-difference bits matches the target bit for 16 +- 6 sqrt(32)/2 of the first 32 kept lanes in the evidence experiment v44-controls-01 (per-bit band; at 32 lanes this 6-sigma band, 16 +- 17.0, is wide and admits every count, so the uniformity evidence for P1 is the pooled count over 20,000 trials, not this check); landing_k4 <= kept/16 + 6 sqrt(kept/16) over all kept lanes. A failed trial returns null messages and reports checks_failed and checks_mask (bits 1, 2, 4, 8, 16, 32, 64 in the order above), so the organizer's byte-identical rerun carries these checks.
